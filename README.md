# Architecture Alexandrite

Проектная работа 6 спринта курса "Архитектор ПО"  
**Модуль:** Кеширование, построение мониторинга и адаптация к высокой нагрузке

## О проекте

Работа над кейсом компании «Александрит» — производителя ювелирных украшений с возможностью индивидуального дизайна через 3D-моделирование.

## Описание системы

Компания «Александрит» столкнулась с проблемами масштабирования при росте нагрузки:
- Линейный рост заказов (~100 дополнительных заказов ежемесячно)
- Открытие API для B2B-клиентов
- Проблемы с производительностью MES-системы
- Потеря заказов и жалобы клиентов

### Текущая архитектура

Система состоит из трёх приложений:
1. **Онлайн-магазин** — Vue + Java Spring Boot
2. **CRM** — SPA (Vue + Java Spring Boot)
3. **MES** — SPA (React + C#)

Интеграция между MES и CRM через RabbitMQ.

### Инфраструктура
- Облако: Yandex Cloud
- Инстансы: EC2
- БД: Managed PostgreSQL (по одному инстансу на запись/чтение)
- Окружения: dev, release, prod

### Основные проблемы
1. Просроченные заказы
2. Медленная загрузка дашборда операторов в MES
3. Потерянные заказы от B2B-клиентов
4. Долгий расчёт стоимости (2-30 минут в зависимости от сложности 3D-модели)

## Статусы заказа

1. `INITIATED` [онлайн-магазин] — новый заказ/корзина
2. `FILE_UPLOADED` [онлайн-магазин] — загружен файл 3D-модели
3. `SUBMITTED` [онлайн-магазин] — заказ отправлен
4. `PRICE_CALCULATED` [MES] — стоимость рассчитана
5. `MANUFACTURING_APPROVED` [CRM] — заказ подтверждён
6. `MANUFACTURING_STARTED` [MES] — заказ взят в работу
7. `MANUFACTURING_COMPLETED` [MES] — заказ выполнен
8. `PACKAGING` [MES] — упаковка заказа
9. `SHIPPED` [MES] — заказ отправлен
10. `CLOSED` [CRM] — заказ завершён

## Команда

**Разработка:**
- 2 фронтенд-инженера Vue (1 частично знает React)
- 2 бэкенд-инженера Java
- 1 разработчик C#
- 1 QA-инженер (ручное тестирование)
- 1 Тимлид (ex-C# разработчик)
- 1 DevOps-инженер
- 1 Продакт-менеджер

**Бизнес:**
- Продавцы (пользователи CRM)
- Операторы (пользователи MES)
- Администраторы

## Процессы

- Спринты: 2 недели
- Ручное E2E-тестирование
- Деплой в dev: автоматически после merge PR
- Деплой в release/prod: вручную
- Блокировка релиза при high/highest багах
