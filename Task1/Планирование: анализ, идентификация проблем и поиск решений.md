# Задание 1. Планирование: анализ, идентификация проблем и поиск решений
## 1. Идентификация проблем

### Критические проблемы 
(далее проблемы буду номеровать с индексом - П, что бы потом на них ссылаться)

П1. Потеря заказов в системе
- Клиенты не получают заказы, особенно B2B через API
- Причина: RabbitMQ без персистентности, нет подтверждений, нет Dead Letter Queue
- Результат: потеря контрактов

П2. Долгий расчет стоимости (2-30 минут)
- Синхронная обработка блокирует систему
- Причина: нет фоновой обработки и кеширования
- Результат: просрочки заказов

П3. Медленная загрузка дашборда MES
- Долгая загрузка списка заказов
- Причина: нет индексов, тяжелые запросы, нет кеша
- Результат: операторы теряют мотивацию

П4. Нет горизонтального масштабирования
- По одному инстансу каждого сервиса
- Причина: нет Load Balancer
- Результат: риск полного отказа

П5. БД без репликации
- Один инстанс PostgreSQL
- Причина: нет read replicas
- Результат: риск потери данных

П6. Нет мониторинга
- Проблемы узнаем от клиентов
- Причина: нет метрик и алертов
- Результат: долгая реакция

Дополнительные проблемы: П7 - нет кеша, П8 - неоптимальная работа с 3D, П9 - медленные релизы, П10 - нет rate limiting

И4. Мониторинг - Prometheus + Grafana (2-3 недели)

## 5. Топ-3 инициативы на ближайшие полгода

### Инициатива 1: Надежность RabbitMQ (И1)

Устраняет потерю заказов, сохраняет B2B контракты.

Что делаем: персистентность, acknowledgments, Dead Letter Queue, retry logic

Результат: 0% потерь заказов (1 Java + 1 C# + 1 DevOps, 2-3 недели)

### Инициатива 2: Мониторинг + Асинхронная обработка (И4 + И2)

А) Мониторинг: Prometheus + Grafana + Alertmanager - время реакции с часов до минут (1 DevOps, 2-3 недели)

Б) Асинхронная обработка: фоновые расчеты через RabbitMQ, воркеры, UI статуса - ответ за секунды, 10x больше заказов (1 C# + 1 React + 1 QA, 3-4 недели)

### Инициатива 3: Оптимизации данных (И3 + И7 + И6)

А) Оптимизация MES: индексы, кеш - загрузка < 1 сек (1 C# + 1 React, 2 недели)

Б) Redis кеш: товары, расчеты, заказы - снижение нагрузки на 60-70%, ускорение в 10-20 раз (2 Java + 1 C#, 2-3 недели)

В) Репликация PostgreSQL: read replicas, pooling - устранение единой точки отказа, +50-100% производительности (1 DevOps + 1 backend, 2 недели)


Эти инициативы покрывают все критические проблемы и реалистичны для команды (3-4 месяца параллельно).Принесет максимальный эффект для бизнеса
